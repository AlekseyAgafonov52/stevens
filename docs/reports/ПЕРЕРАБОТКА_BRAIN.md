# Переработка резервного ИИ-разбора — 24.10.2026

Выполнен согласованный первый этап: безопасная переработка существующих LLM-команд — создание задач, встреч и напоминаний, списки, поиск, помощь, благодарность и ответ на посторонний запрос. Перенос, удаление, выполнение, голосовые исправления и другие новые действия через нейросеть в этом этапе не включались. Их реализация правилами продолжает работать.

## Что изменилось

`brain.py` теперь содержит только точку входа `parse_user_input`. Выделены:

- `app/ai/schema.py` — вход §5.1 и структура выхода §5.2 контракта v1.6, включая готовые ISO-даты, время HH:MM, числовую уверенность, сомнения и слой разбора;
- `app/ai/provider.py` — запрос к Yandex, чтение ответа, классификация ошибок и проверка схемы;
- `app/ai/adapter.py` — перевод поддержанного результата в существующий `nlu.Parse`, без доступа к БД и исполнения действий;
- `app/routers/chat.py` — передача контекста и обработка результата через прежнюю логику диалога.

Старый `IntentSchema` с `create_task/create_meeting/create_reminder`, датами-токенами и строковой уверенностью удалён. Вызов `parse_user_input` сохранён, но его результат — новый `Result`; внутренние потребители и тесты обновлены. HTTP API сайта и структура ответов Stevens не менялись.

Нейросеть получает `text`, `now`, `timezone`, `source`, `awaiting`, `focus`, `last_query`. Фокус загружается с проверкой владельца. Из незавершённого диалога выбираются публичные сведения о вопросе и записи; токены и сведения владельца в контекст не добавляются. Дата со смещением берётся из запроса пользователя. Правила по-прежнему вызываются первыми.

Удалены фиксированная дата `2026-11-06`, догадки о намерении по отдельным словам после ответа `unknown`, дублирующий перевод дат-токенов и очистка названий регулярными выражениями. Название «Подготовить отчёт 25» сохраняет число. Даты разрешает модель относительно переданного `now`; код проверяет существование даты, а прежняя логика приложения проверяет прошлое и конфликты.

## Проверка ответа и отказ

- Принимается один вызов `extract_intent` либо один JSON-объект; допускается оболочка блока `json`. Несколько вызовов, неизвестная функция, текст с произвольной вставкой JSON, повторяющиеся ключи и NaN отклоняются.
- Неизвестные поля, неверное намерение, несуществующая дата, время вне HH:MM, некорректная уверенность и неполные причины сомнения отклоняются. Длинное название не обрезается до другого значения, а делает разбор непригодным.
- `layer` от нейросети должен быть `llm`. Схема описывает и будущие намерения, но отдельный список в адаптере разрешает только текущий согласованный набор команд и типов создания.
- Создание с уверенностью ниже 0,5 не выполняется. Принятое создание обязательно содержит сомнение `llm` и проходит существующее подтверждение черновика. Для списков/поиска требуется уверенность не ниже 0,8. Общий новый сценарий подтверждения других намерений не добавлялся.
- Несколько готовых дел показываются существующим подтверждением пакета. Неполный пакет не превращается в молчаливое создание только первого дела.
- Таймаут SDK — 10 секунд, автоматические повторы отключены. Дополнительно обработчик ограничивает ожидание фонового вызова общим сроком 10 секунд. После сбоя или неверного ответа резервный вызов приостанавливается на минуту; сохраняется результат правил.
- Различаются отсутствие ключей, таймаут, ограничение частоты, ошибка авторизации провайдера, другая ошибка API и неверный ответ. В ошибку журнала не выводятся ключи, полный ответ SDK или его исключение с телом запроса. Полный проверенный результат, статус и время LLM доступны в `ctx.trace`; постоянный журнал использует прежние поля `llm`, `intent`, `error`, общий `ms`.

Попутно исправлена потеря `remind_before: 0` при сборке черновика: ноль больше не заменяется стандартными 15 минутами.

## Уточнение правил — 25.10.2026

Исправлены два примера из ручной проверки:

- «Будь добр, помоги мне не забыть: завтра к 11 надо подготовить отчёт 25.» → задача «Подготовить отчёт 25», завтра, 11:00.
- «Мне бы завтра в 15 пересечься с Иваном, организуй это как встречу.» → «Встреча с Иваном», завтра, 15:00.

Время распознаётся также после «к/ко»; номера вроде «11 класс» и даты вроде «к 11 ноября» не превращаются в часы. Вводные удаляются только в начале запроса, а явная завершающая инструкция «организуй это как встречу» — после запятой или точки с запятой. Значимые числа в названиях сохраняются.

Нейросеть теперь может уточнять не только `unknown`, но и создание задачи/встречи/напоминания с `unclear`, остатком времени или неразобранной вводной в названии. Такой результат правил оценивается как 0,5; принимается только пригодный LLM-разбор с большей уверенностью. После замены остаётся подтверждение создания. При сбое, `unknown`, неподдержанном намерении или не более уверенном ответе сохраняется разбор правил с подтверждением. Отвергнутый пакет LLM не используется частично.

Для уверенного разбора этих двух исправленных примеров вызова LLM нет — `llm = false` в журнале ожидаем. Вызов, результат которого отвергнут, может иметь `llm = true`: это признак попытки; `llm_used` в трассе отдельно показывает принятие результата.

Проверки: `python tests/test_nlu_refinement.py` — 13 тестов правил и безопасного дополнительного разбора без запросов Yandex. Все 25 серверных тестовых файлов прошли на отдельной БД; Pyright — без ошибок и предупреждений. Оба примера дополнительно проверены целиком через API, включая последующее «Нет, в 16» для встречи. Изменены `app/nlu.py`, `app/routers/chat.py`, `README.md`, `СТАБИЛЬНАЯ_ВЕРСИЯ.md`, этот отчёт; добавлен `tests/test_nlu_refinement.py`. Запуск прежний: `docker compose up --build -d`.

Дополнительно исправлена фраза «Я вчера забыл помыть посуду, напомни завтра». Для конструкции «забыл/не успел …, напомни …» прошлое событие служит контекстом, а день напоминания берётся из явной просьбы. Если в просьбе нет собственного названия, наследуется забытое действие — «Помыть посуду». Если названо другое дело («напомни завтра купить молоко»), сохраняется оно. Прошлые дата и время из описания забытого дела не наследуются новым напоминанием. Отсутствующее время уточняется стандартным вопросом, без преждевременной записи. Проверен полный API-диалог: вопрос → «в 11» → ровно одно напоминание на завтра в 11:00.
