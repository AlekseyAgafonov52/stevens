# Исправления надежности и безопасности Stevens

24 октября 2026 года. Изменения сделаны поверх `b9e90cc`; старые аудиты сохранены как история проверки.

## Результат

Закрыт первый приоритетный блок: сохранность импорта и повторов, длинные пароли, опасные push-адреса, обработка сбоев доставки, ограничения запросов и основной сценарий интерфейса. Добавлены контрактные endpoints импорта v1.6 и его отмена. Код приложения проверялся на отдельной базе; работающие пользовательские контейнеры не перезапускались.

### Сохранность данных

- Новый импорт: `GET /api/records/export`, `POST /api/records/import/preview`, `/apply`, `/undo`.
- Экспорт содержит полные `Record[]`: сроки задач, свойства уведомлений, каждый день повтора и его индивидуальные правки.
- Preview не меняет БД. Ошибка любой строки запрещает весь пакет; сбой до commit откатывает изменения.
- Отсутствующие во входном снимке существующие записи мягко удаляются. Пустой импорт отвергается. При удалении больше 10 записей интерфейс требует подтверждение.
- Apply возвращает `undo_id`; отмена доступна владельцу 2 часа. Повторная отмена и отмена чужого импорта запрещены. Если после импорта пользователь изменил затронутую запись, undo возвращает 422 и не затирает эту правку.
- Изменение события повтора в новом импорте касается одного дня, а не всей серии. Для совместимости старые `/api/transfer/*` оставлены, но их применение тоже стало атомарным; на фронте используются новые адреса.
- Встреча/напоминание серии не сохраняется без времени. Конечные серии дольше года продлеваются до `until`; дата ограничена календарными границами.
- Сброс песочницы удаляет также серии и snooze, чтобы повтор не создавал заново сброшенные записи. Подписка браузера сохраняется.

### Авторизация и ограничения

- Новые пароли — Argon2id, без усечения окончания. Короткий старый bcrypt проверяется и обновляется при успешном входе.
- По согласованному решению старые bcrypt-пароли на границе 72 UTF-8 байт и длиннее отклоняются. Именно на 72 байтах нельзя отличить полный старый пароль от префикса ранее усеченного длинного; прием этого префикса оставил бы уязвимость. Для этих аккаунтов нужна отдельная административная смена пароля; нового публичного reset-endpoint в контракт не добавлялось.
- Регистрация/вход сохраняют контрактные поля и ошибки. Токены живут 30 дней. Ключи и пароли не выводятся в тестовые логи.
- Ограничения частоты: auth — 30/мин на IP; STT — 30/мин; импорт/выгрузка — 20/мин; reset — 10/мин; остальные API — 180/мин. Дополнительно ограничивается владелец; первые обращения с новыми X-Client-Id — 10/мин на IP.
- Превышение дает согласованные `429 {"error":"rate_limited"}` и `Retry-After`; фронт использует существующую русскую ошибку.
- Параллельность на процесс: auth — 2, STT — 4, чат — 8, импорт/экспорт — 2. Это ограничивает память Argon2 и очереди медленных операций. Ожидание свободного слота ограничено.
- Тело запроса ограничивается при чтении потока: auth 4 КиБ, обычный JSON 64 КиБ, импорт 8 МиБ, аудио 1 МиБ. Чтение ограничено по времени. Новый импорт допускает до 10 000 входных записей, старый импорт ограничивает развертывание повторов.
- Лимитер и кэш диалогов ограничены по памяти. У диалога теперь действительно истекает срок 2 часа; LRU удерживает максимум 5000 состояний на процесс.
- `X-Forwarded-For` игнорируется, пока точный IP proxy не внесен в `STEVENS_TRUSTED_PROXIES`. Автоматическое доверие forwarded-заголовкам Uvicorn отключено.
- В Compose порты БД и прямого API привязаны к `127.0.0.1`. CORS задается списком `STEVENS_CORS_ORIGINS`; `*` больше не используется.

### Уведомления и голос

- Push разрешен только на доверенные сервисы Google FCM, Mozilla, Apple и Windows. Запрещены credentials в URL, неожиданные порты, перенаправления и соединения с непубличными адресами. Используются проверка TLS и HTTP-session без proxy из окружения.
- Ключи подписки проверяются как EC P-256 и 16-байтовый auth. Одного endpoint недостаточно, чтобы подменить сохраненные ключи; штатный перенос той же браузерной подписки между песочницей и аккаунтом сохранен.
- Временная ошибка доставки не создает отметку успеха. Успех учитывается отдельно для каждой подписки; повторный tick не повторяет уже успешную отправку. Snooze остается в очереди при временном сбое.
- Фоновая очередь защищена PostgreSQL advisory lock между процессами. VAPID-ключ выбирается атомарно из БД; конкурирующая инициализация не выдает временный ключ другого процесса. Разные timezone подписок обрабатываются отдельно.
- Отписка и snooze по секретному endpoint сохранены: это прямо задано контрактом для service worker. Полной замены этой модели авторизации на другой протокол не делалось.
- Для `/api/stt` добавлен отдельный слой `app/voice`: WebM/Ogg преобразуется в одноканальный Ogg Opus, длительность проверяется, слишком длинное аудио не обрезается молча. Для синхронного API SpeechKit нужны одноканальные LPCM/OggOpus, до 30 секунд и 1 МБ. [Официальные требования](https://aistudio.yandex.ru/ru/docs/speechkit/stt/request).
- ffmpeg/ffprobe входят в Docker-образ. Аргументы передаются без shell; входной контейнер и протоколы ограничены, процессы имеют timeout и завершаются при отмене. С API-ключом сервисного аккаунта `folderId` в запрос STT не добавляется. [Документация API](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/request-api).

### Основной сценарий

- Создание, удаление, выполнено и «Отменить» больше не требуют неописанного контрактом legacy-заголовка. Явно присланные старые флаги оставлены для совместимости.
- Серверные флаги проверяются для основных кнопочных действий, в том числе удаления и отметки.
- Исправлена фраза v1.6 «напоминание: оплатить интернет» с последующим уточнением даты/времени.
- Экран импорта показывает preview/ошибки, блокирует применение ошибочного пакета, подтверждает большие удаления, закрывается после успеха и выводит результат с кнопкой «Вернуть» в ленту. Календарь обновляется.
- Общая проверка записей вынесена в слой логики: REST и импорт используют один валидатор.

- Отдельные регрессии: rollback после искусственного сбоя, неизвестные/неверные id, чужой/повторный undo, поздняя правка, длинные UTF-8 пароли, миграция bcrypt, обход rate limit через поддельный forwarded-заголовок, ограничение чтения аудиопотока, временные ошибки push и snooze.

## Как запустить изменения

Из корня проекта:

```powershell
docker compose up --build -d
```

Открыть `http://localhost:8081`, API — `http://localhost:8000/docs`. Пересборка добавит ffmpeg и Argon2; при старте создастся новая таблица `import_operations`. Существующий volume БД сохраняется. `docker compose down -v` для обновления не нужен.

На рабочем стенде команда еще не выполнялась: пользовательская база и работающие контейнеры не менялись. Проверочный стенд был отдельным.

Для прямого запуска Python дополнительно нужны ffmpeg и ffprobe в PATH. Без них серверное STT возвращает контрактный 503; обычный чат продолжает работать.

Настройки:

- `STEVENS_CORS_ORIGINS` — основной/запасной адреса фронта и нужные localhost-адреса.
- `STEVENS_RATE_LIMIT=1` — нормальный режим; `0` допустим только для локальных регрессионных прогонов.
- `STEVENS_TRUSTED_PROXIES` — точные IP доверенных proxy. Без настройки несколько клиентов за одним proxy делят IP-лимит. Proxy должен перезаписывать X-Forwarded-For адресом реального клиента; nginx проекта это делает.
- `TZ` — пояс, указываемый в выгрузке; по умолчанию `Europe/Moscow`.

Лимиты находятся в памяти процесса. Для нескольких реплик нужен общий limiter на ingress/в общем хранилище; это не заменяется умножением локальных лимитов.

## Как повторить проверки

Нужна отдельная PostgreSQL, не пользовательская база. Runner использует только `stevens_audit` на `127.0.0.1:55439` с тестовым паролем и отключает загрузку рабочего `.env`.

```powershell
docker run -d --name stevens-regression-db -e POSTGRES_PASSWORD=audit_local_only -e POSTGRES_DB=stevens_audit -p 127.0.0.1:55439:5432 postgres:16-alpine
docker exec stevens-regression-db pg_isready -U postgres -d stevens_audit
# Продолжать после сообщения accepting connections.
$env:AUDIT_OUT_DIR = 'fix-results/recheck'
python audit_run_tests.py
docker rm -f -v stevens-regression-db
```

Из `frontend-contract`: `pnpm run lint`, `pnpm run typecheck`, `pnpm test`, `pnpm run build`. Те же команды выполняются в Docker build.

Для браузерной проверки нужны отдельный стенд на `127.0.0.1:18081` и Edge с временным профилем/CDP на `127.0.0.1:19222`; затем `python tools/check_browser_flow.py`. Для аудио — запуск `tools/check_audio_conversion.py` внутри собранного backend-образа с ffmpeg. В этих проверках не используются рабочие ключи Yandex и реальные push-подписки.

## Что осталось отдельными задачами

- Настоящие микрофон/динамики, Safari/iPhone, качество STT/LLM у провайдера и доставка push на устройство: проверить на оборудовании и с рабочими ключами. Headless и mock-транспорт это не доказывают.
- Замена стандартного пароля/роли PostgreSQL в существующем volume, production HTTPS, backup и запасной хостинг. Привязка портов к localhost ограничивает сетевой доступ, но не выполняет эти административные действия. Смена переменной POSTGRES_PASSWORD сама по себе не меняет пароль уже созданной БД.
- Единый JSON стыка ИИ v1.6, полная миграция остальных стыков и согласование противоречивых Т6/Т25-1. Этот блок не объявляет весь проект полностью соответствующим v1.6.
- Доработки, не входившие в приоритетный блок: точные ответы/кнопки занятости, учет выходных, полнота метрик журнала и оставшиеся граничные фразы.

Временные контейнеры/сеть проверки удалены; рабочие `voice_assistant-*` оставлены работающими. Локальные собранные образы сохранены; временные логи исключены из Git.

## Дополнительная проверка chat.py

Весь `app/routers/chat.py` проверен Pyright 1.1.414: первоначально 48 ошибок, после исправлений — 0 ошибок и предупреждений. Диагностики не отключались; `cast` и `type: ignore` для их обхода не добавлялись.

Добавлены явные проверки обязательных дат и времени перед вычислениями; отсутствующее время не заменяется полуночью. Исправлена работа с необязательным типом записи, отсутствующим вопросом уточнения, интервалом напоминания и идентификатором серии. Пустая группа переноса возвращает контрактный ответ вместо `None` или обращения к `rows[0]`. Повторяющаяся занятость с `end_time: null` уточняет время окончания.

Изменён `app/routers/chat.py`, добавлен `tests/test_chat_safety.py`: 8 тестов проверяют границы времени, текущую занятость, неполный повтор, отсутствие серии и предотвращение частичной записи при неизвестном типе.

После исправлений успешно выполнены все 21 существующий серверный тестовый файл на отдельной PostgreSQL и 8 новых проверок без БД. В логах нет `FAIL`, `BAD`, исключений или ошибок обработчика чата. Тестовый контейнер удалён, рабочий сервис не перезапускался.

Запуск приложения прежний: `docker compose up --build -d`. Проверка без БД: `python tests/test_chat_safety.py`. Статический анализ: `npx --yes pyright@1.1.414 app/routers/chat.py`. Полные серверные проверки запускаются на отдельной БД командой из раздела выше.
