# Запуск и проверка Stevens

## Приложение

Нужен Docker Desktop с Linux-контейнерами. Из корня репозитория:

```sh
docker compose up --build -d
docker compose ps
```

Сайт: http://localhost:8081 или http://localhost:8080. API: http://localhost:8000/docs. Проверка доступности: http://localhost:8000/api/health.

Регистрация: логин 3–32 символа, пароль 5–128 символов. Можно выбрать песочницу без регистрации. Аккаунт создаётся пустым; песочница содержит демо-записи.

Без ключей Yandex работают авторизация, записи, календарь и разбор поддержанных фраз правилами. Для STT и резервного LLM заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в локальном `.env` по `.env.example`, затем пересоздайте backend. В браузере разрешите микрофон; вне localhost для него требуется HTTPS.

Compose запускает `frontend-contract/`. Каталог `frontend/` предназначен для прежнего API.

Остановка с сохранением данных:

```sh
docker compose down
```

Данные находятся в Docker volume. Для применения изменений используйте `docker compose up --build -d`; обычный перезапуск контейнеров не пересобирает код.

## Локальные проверки Python

Нужен Python 3.13. В виртуальном окружении установите зависимости:

```sh
python -m pip install -r requirements-dev.txt
npx --yes pyright@1.1.414
python tests/test_chat_safety.py
python tests/test_project_safety.py
```

Для Pyright через npx нужен Node.js/npm. Настройки анализа всего Python-кода находятся в `pyrightconfig.json`.

## Полный серверный прогон

Используйте отдельную БД. `audit_run_tests.py` принудительно направляет проверки на `127.0.0.1:55439/stevens_audit`, отключает внешние ключи и загрузку `.env`; рабочий Compose не используется.

```sh
docker run -d --name stevens-regression-db -e POSTGRES_PASSWORD=audit_local_only -e POSTGRES_DB=stevens_audit -p 127.0.0.1:55439:5432 postgres:16-alpine
docker exec stevens-regression-db pg_isready -U postgres -d stevens_audit
```

Дождитесь `accepting connections`, затем:

```sh
python audit_run_tests.py
```

Выборочная проверка: `python audit_run_tests.py test_chat_safety.py test_project_safety.py`. Логи и JSON со статусами записываются в игнорируемый каталог `audit-results/`. Ненулевой код означает ошибку, таймаут или напечатанный провал старого теста. При выборочном прогоне сохранённые провалы других файлов также оставляют общий статус неуспешным.

Удалить только тестовую БД после завершения проверок:

```sh
docker rm -f -v stevens-regression-db
```

## Фронтенды

В нужном каталоге (`frontend-contract/` или `frontend/`) с Node.js 22.13+ и pnpm 11.25.0:

```sh
pnpm install --frozen-lockfile
pnpm run lint
pnpm run typecheck
pnpm test
pnpm run build
```

Можно проверить без локальной установки зависимостей: `docker build --target build frontend-contract` и отдельно `docker build --target build frontend`.

`tools/check_browser_flow.py` требует отдельный стенд на порту 18081 и Edge с временным профилем/CDP на 19222. `tools/check_audio_conversion.py` запускается в backend-образе с ffmpeg; транспорт STT подменён и запросов провайдеру не отправляет. Подробности общей проверки — в `СТАБИЛЬНАЯ_ВЕРСИЯ.md`.
