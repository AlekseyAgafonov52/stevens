# Стивенс — голосовой ассистент для задач, встреч и напоминаний

Стивенс понимает свободную русскую речь и текст: записывает задачи, напоминания и встречи, показывает планы за любой период, находит старые записи по смыслу и отвечает голосом. Когда данных не хватает, переспрашивает («Во сколько встреча?»), а при совпадении времени предлагает решить конфликт.

- **Прототип:** <ссылка на стенд> — можно войти по логину или открыть песочницу без регистрации (в ней 1000 событий из датасета задания).
- **Демо за 3 минуты:** [DEMO.md](DEMO.md).

## Запуск

Нужен Docker Desktop (Linux-контейнеры). В корне репозитория:

```sh
docker compose up --build -d
```

Сайт: http://localhost:8081, API и его документация: http://localhost:8000/docs.

Без ключей всё работает на правилах, кроме распознавания речи на сервере и запасного разбора через LLM. Чтобы их включить, скопируйте `.env.example` в `.env`, впишите `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (Yandex Cloud, роли `ai.languageModels.user` и `ai.speechkit-stt.user`) и перезапустите `docker compose up -d --build backend`. Ключи хранятся только на сервере. Подробные команды, тесты и резервные копии описаны в [ЗАПУСК.md](ЗАПУСК.md).

## Что умеет

| Требование задания | Как сделано |
| --- | --- |
| Создание задачи или напоминания | «Напомни завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «…до конца недели» (срок) |
| Создание встречи | «В четверг в 11 у меня встреча с дизайнером»; проверка пересечений: «другое время», «перенести существующую», «оставить обе» |
| События за период | сегодня, завтра, послезавтра, день недели, «эта / следующая неделя», «выходные», «ближайшие 10 дней», «сегодня и завтра», месяц, «все дела», «невыполненные», «просроченные» |
| Поиск старых записей | «Когда у меня была встреча с Иваном?», «Я когда-то ставил задачу по договору»; падежи и уменьшительные имена («Ваня» = «Иваном»), смысловые группы («про деньги» находит бюджет, «контракт» — договор, «слайды» — презентацию) |
| Естественный язык | без команд: «Что у меня сегодня?» = «Какие планы на сегодня?» = «Покажи мои встречи на сегодня»; «через два часа», «в половине третьего», вставные слова |
| Уточнение | «Поставь встречу с Иваном завтра» → «Во сколько встреча?» с кнопками свободных часов; при сомнении — «Верно понял: …?» |
| Хранение | PostgreSQL: тип, текст, дата, время, срок или точный момент, статус, дата создания |
| Голос | микрофон → распознавание → ответ текстом и голосом; вызов по имени «Стивенс» |

Дополнительно (плюсы из задания): изменение и удаление голосом, отметка «выполнено» («Я позвонил Ивану»), конфликты встреч, повторы («каждый понедельник в 10 планёрка»), контекст диалога («перенеси её на завтра», «а встречи?»), несколько дел в одной фразе, несколько пользователей (логин и пароль) и песочница, импорт из `.ics` и JSON, календарь с перетаскиванием, push-напоминания и вечерняя сводка просроченного.

## Архитектура

```
Браузер (React + TypeScript)
  микрофон → Web Speech API или POST /api/stt (Yandex SpeechKit) → текст
  ответ ← карточки записей + озвучка speechSynthesis
        │  POST /api/chat {text, conversation_id, client_time}
        ▼
FastAPI
  1. Понимание   app/nlu.py — правила и морфология (pymorphy3): намерение, тип, даты, время, ключи поиска
                 app/ai/ — запасной путь: YandexGPT, только если правила не поняли фразу или сомневаются;
                 ответ модели проверяется строгой схемой (app/ai/schema.py), модель ничего не меняет сама
  2. Диалог      app/routers/chat.py — память разговора (что спросили, о какой записи речь), уточнения,
                 конфликты, «её/эти две», выбор шаблона ответа (app/templates.py)
  3. Логика      app/logic/ — проверка записей, импорт, лимиты запросов, адресаты push
  4. Хранение    app/models.py + PostgreSQL 16 (async SQLAlchemy), app/owner.py — аккаунт или песочница
```

Голос, понимание, бизнес-логика и хранение разделены: фронт ничего не знает о разборе, правила и LLM возвращают одну и ту же структуру `Parse`, логика работает только с ней, а база не знает о диалоге.

**Технологии:** Python 3.13, FastAPI, SQLAlchemy (async) + asyncpg, PostgreSQL 16, pymorphy3, dateparser, YandexGPT через OpenAI-совместимый API, Yandex SpeechKit, argon2; React 19, TypeScript, Vite; Docker Compose и nginx.

## Решения, которые мы приняли сами

- **Сначала правила, LLM только как запасной путь.** Типовые фразы разбираются за 10–90 мс без сети и одинаково каждый раз. LLM подключается только для непонятных фраз и не может выполнить действие без проверки схемой.
- **Не угадываем молча.** Нет времени у встречи — переспрашиваем. Есть сомнение («или», «наверное», ослышка) — показываем черновик и спрашиваем «Верно?». Новую запись не создаём, пока не закончили с прошлой.
- **Тип записи выводим из текста.** В датасете типа нет: «Встреча», «Созвон», «Демо» — встречи, «Напомнить» — напоминания, остальное — задачи.
- **Поиск по смыслу без внешних сервисов.** Падежи снимает морфология, синонимы разложены по смысловым группам, а имена учитывают уменьшительные формы. Это работает и без ключей.
- **Песочница.** В неё можно попасть без регистрации, внутри 1000 событий из задания. Её можно сбросить кнопкой.
- **Ответы по шаблонам.** У каждого ответа есть несколько вариантов формулировки, чтобы речь не звучала одинаково, а для озвучки отдельная версия текста.

## Проверки

```sh
python tests/test_jury_phrases_api.py
python tests/test_contract_v16.py
python tests/test_ai_parser.py
```

`tests/test_jury_phrases_api.py` прогоняет все примеры из задания и их пересказы: 36 фраз, все проходят. Всего в `tests/` 37 файлов, им нужна отдельная тестовая PostgreSQL (см. [ЗАПУСК.md](ЗАПУСК.md)). Фронтенд проверяется `pnpm run lint`, `typecheck`, `test` и `build` при сборке образа.

## Что улучшили бы при наличии времени

- Векторный поиск (эмбеддинги Yandex) в дополнение к смысловым группам, чтобы находить записи по описанию без общих слов.
- Распознавание речи потоком, чтобы текст появлялся во время речи во всех браузерах, а не только в Chrome.
- Синхронизация с Google и Яндекс Календарём в обе стороны (сейчас есть только импорт `.ics`).
- Разделение `app/routers/chat.py` на модули по сценариям и общий набор тестов под pytest с CI.
- Обучение правил на журнале реальных запросов: фразы, которые не поняли правила, но понял LLM, превращать в новые правила.
