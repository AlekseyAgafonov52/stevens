# Правила для ИИ-агента — фронтенд Stevens

Ты пишешь фронтенд голосового и текстового ассистента Stevens (React + TypeScript + Vite). Все продуктовые и дизайнерские решения уже приняты и описаны в `docs/`. Твоя задача — реализовать их точно, а не придумывать.

Это **вариант 2 — с допами**: первый вариант (без допов) плюс допы под флагами. Все флаги допов выключены — должен получиться в точности первый вариант.

## Жёсткие правила

1. **Тексты** — только из `src/content/texts.ts`. Не писать строки для пользователя в компонентах. Не хватает текста — остановись и скажи, не придумывай.
2. **Цвета, скругления, тени, длительности** — только через CSS-переменные из `tokens.css`. Ни одного `#hex`, `rgb()`, `rgba()` в компонентах. **Размеры и отступы** — токеном, если он есть; если токена нет, но число прямо записано в `docs/02`, `04`, `07` или `08` (ширина колонки входа 400, панель 340, ячейка 40 и т. п.) — можно числом в CSS компонента, с комментарием-ссылкой на раздел документа. Числа, которого нет ни в токенах, ни в документах, не придумывать — скажи.
3. **Фразы ассистента и кнопки ответа** приходят от бэка. Фронт их не сочиняет, не переписывает и не добавляет своих (исключения — «Повторить» у ошибки и «Исправить» у созданной записи, доп Д10).
4. **Рендер по общим полям ответа.** `kind` — подсказка оформления. Незнакомый `kind` рисуется по `text` / `records` / `buttons`, не ломает интерфейс.
5. **Все запросы** — только через модуль `src/api/`. Компоненты не вызывают `fetch`.
6. **«Сейчас»** — только через `now()` из `src/lib/clock.ts`.
7. **Голос** — только через модуль `src/voice/` с его интерфейсом.
8. **localStorage** — только через `src/storage/`, каждое обращение в `try/catch`.
9. **Флаги:** выключенная функция не рисуется совсем. Не включать допы самостоятельно. Допы встраиваются только через точки расширения из `docs/09-extensions.md`, живут в `src/extras/<доп>/`, грузятся динамическим импортом. Первый вариант под допы не переписывается.
10. **Иконки** — `lucide-react`, `strokeWidth={1.5}`, по таблице из `docs/04-style.md`.
11. **Не добавлять** UI-библиотеки (MUI, Chakra, Tailwind и т. п.), аналитику, внешние шрифты, новые цвета, эмодзи, градиенты, тени у карточек.
12. **Доступность:** кнопки-иконки с `aria-label`, обводка фокуса через `:focus-visible`, лента с `aria-live="polite"`.
13. **Качество кода:** TypeScript strict без `any`, мелкие компоненты, логика отдельно от отрисовки, понятные имена. Перед сдачей шага — `npm run lint && npm run typecheck && npm test`.
14. **Проверка флагов:** после любого изменения в допе — выключить все флаги допов и прогнать эталонные снимки первого варианта; расхождений быть не должно.
15. **Персонаж** — только готовые SVG из `src/assets/mascot/` (inline, не `<img>`) и стили из `src/styles/mascot.css`. Не перерисовывать, не менять пропорции и цвета. `mascot.css` и `tokens.css` — готовые файлы, их числа не считаются «магическими». Тайминги цикла «пишет» из `08-mascot.md`, раздел 4 (1,2 с, 1,6 с, кадры по 200 мс, смена 150 мс, пауза печати 1,5 с, «готово» / «не понял» 3 с) — константами в одном файле кода допа.

## Когда остановиться и спросить

- Документы противоречат друг другу или чего-то не хватает для экрана или поведения (кроме расхождения текста и картинки — там прав текст).
- Хочется изменить вид, текст или поведение «чтобы было лучше».
- Бэк отвечает не по контракту.

Технические решения (структура кода, состояние, вспомогательные библиотеки без UI, сборка, тесты) — принимай сам и коротко объясняй.

## Как работать

Иди по шагам `docs/06-build-plan.md`. Перед шагом перечитай указанные в нём разделы. После шага — покажи, как проверить по пункту «Готово, если».
