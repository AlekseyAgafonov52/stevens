# 05. API

Полный контракт с бэком: первый вариант — `reference/contract_v1.3.pdf`; с допами — `reference/contract_v1.4_s_dopami.pdf` (раздел 15). Типы — `src/api/types.ts`. Здесь — то, что нужно фронту. Вход и песочница (раздел 14 контракта) ещё ждут подтверждения бэка.

Все запросы — только через один модуль `src/api/`. В нём переключатель «заглушки / настоящий бэк» (`apiMode` в `features.ts`). Остальной код не знает, откуда пришёл ответ.

## Эндпоинты

| Метод и путь | Заголовок режима | Зачем | Версия |
|---|---|---|---|
| `GET /api/health` | — | жив ли сервер → `{ "status": "ok" }` | v1.2 |
| `POST /api/chat` | да | любое сообщение: текст, голос, кнопка | v1.2 |
| `POST /api/auth/register` | — | `{ login, password }` → `{ token, user }` | v1.3, ждёт бэка |
| `POST /api/auth/login` | — | `{ login, password }` → `{ token, user }` | v1.3, ждёт бэка |
| `POST /api/auth/logout` | `Authorization` | → 204 | v1.3, ждёт бэка |
| `GET /api/auth/me` | `Authorization` | → `{ user }` или 401 | v1.3, ждёт бэка |
| `POST /api/sandbox/reset` | `X-Client-Id` | демо-данные песочницы заново → 204 | v1.3, ждёт бэка |
| `POST /api/stt` | — | аудио → текст, если браузерное распознавание не взлетит | резерв |
| `GET /api/records?from=&to=` | да | записи за период — календарь (Д6) | v1.4, допы |
| `PATCH /api/records/{id}` | да | правка и отметка (Д10, Д6, Д3) | v1.4, допы |
| `DELETE /api/records/{id}` | да | мягкое удаление в календаре (Д2) | v1.4, допы |
| `POST /api/records/{id}/restore` | да | «Вернуть» в календаре (Д2) | v1.4, допы |

**Заголовок режима:** `Authorization: Bearer <token>` в аккаунте, `X-Client-Id: <uuid>` в песочнице. Ровно один.

**Заголовок допов** (только `POST /api/chat`, только если включён хотя бы один из `d2`, `d3`, `d10`): `X-Stevens-Features: d2,d3,d10` — перечислить включённые. Подробно — `09-extensions.md`, правило 7.

## Общие правила

- JSON, UTF-8. Поля и значения-перечисления — на английском, тексты для людей — на русском.
- Дата записи `"YYYY-MM-DD"`, время `"HH:MM"` — местные, без пояса. Моменты (`client_time`, `created_at`) — ISO со смещением.
- «Сегодня» бэк берёт из `client_time`, а не из своих часов.
- Ответ ассистента, включая «не понял», — всегда 200. 422 — неверный запрос, 500 — сбой, 401 — плохой токен.
- Таймаут фронта — 25 с (60 с, пока сервер просыпается).
- HTTPS обязателен (без него браузер не даст микрофон). Бэк разрешает CORS для домена фронта и `http://localhost:5173`, методы `GET`, `POST` и заголовки `Authorization`, `X-Client-Id`, `Content-Type`. **С допами** — ещё методы `PATCH`, `DELETE`, `OPTIONS` и заголовок `X-Stevens-Features` (контракт v1.4, раздел 3). Если с настоящим бэком правка или удаление падают с ошибкой CORS — это сюда, передать бэку.

## Ответ `POST /api/chat` — коротко

Одна структура на всё (`ChatResponse`): `kind`, `text`, `records`, `nearest`, `total`, `awaiting_reply`, `buttons`, `speech`. `kind` — только подсказка оформления.

| kind | Что показать |
|---|---|
| `created` | текст + созданная карточка с подсветкой |
| `list` | текст + карточки по дням; пусто — текст + «Ближайшее» (`nearest`) |
| `found` | текст + плоский список (5, потом по 10), подпись лимита при `total` > длины `records`; у записей может быть `highlight` |
| `clarify` | вопрос + кнопки-подсказки и «Отменить» |
| `confirm` | вопрос + карточка-черновик + «Да, верно» / «Нет» |
| `conflict` | вопрос + черновик + совпадающие встречи + кнопки выбора |
| `cancelled`, `thanks` | только текст |
| `not_understood`, `off_topic`, `help` | текст + примеры кнопками |
| `error` | текст как ошибка + «Повторить» (кнопку добавляет фронт) |
| незнакомый | по общим полям, как есть |

## Кнопки

`Button = { label, send: { text } | { action }, style? }`. Нажатие → `POST /api/chat` с `source: "button"`, `text` = `send.text` или `label`, `action` = `send.action` или `null`.

Действия первого варианта: `cancel`, `confirm_yes`, `confirm_no`, `keep_both`, `change_new_time`, `move_existing` (с `record_id`). Действия допов (контракт v1.4, 15.3): `undo` (Д10), `restore` и `delete` (Д2), `complete` (Д3) — все с `record_id`. Фронту не нужно знать смысл действий: он просто отправляет то, что прислал бэк.

## Вход и песочница (раздел 14 контракта)

**Ошибки:** `{ "error": "<код>" }` — `invalid_credentials` (401), `login_taken` (409), `invalid_login` / `invalid_password` (422).

**Правила бэка, на которые опирается фронт:**
- Неизвестный `X-Client-Id` → бэк создаёт песочницу с копией демо-данных. Изменения хранятся за этим id.
- Регистрация создаёт **пустой** аккаунт. Песочница при этом не переносится.
- Вход на другом устройстве — без слияния с песочницей.
- Логин сравнивается без учёта регистра; правила логина и пароля — как в `03-behavior.md`, раздел 8 (бэк проверяет тоже).

Если бэк поменяет формат — правится только модуль `src/api/` и `types.ts`.

## Заглушки

`src/api/mocks.json` — ответы на фразы из примеров, тестовых сценариев и все действия кнопок; особые фразы `#network`, `#timeout`, `#slow`, `#500`, `#401`, `#wake`, `#conflict_many`, `#list_mixed`, `#unknown_kind`, `#backend_error` — для проверки состояний. Правила сопоставления и поддельные «сейчас» — в `meta` файла.

**Заглушки допов** (правила — в `meta` файла):
- `meta.extras` — сценарии «ДОП» и кнопки `undo` / `restore` / `delete` / `complete` работают, только если доп включён; иначе ответ как в первом варианте.
- `meta.store` — одно хранилище записей в памяти на чат и календарь (старт — `mock-records.json`): ответы чата и REST допов меняют его, поэтому календарь видит записи из чата.
- `meta.patch` — как заглушка `PATCH` меняет запись (то же, что контракт v1.4, 15.5).
- Если в `match` есть `record_id`, совпасть должен и `action.record_id`.
