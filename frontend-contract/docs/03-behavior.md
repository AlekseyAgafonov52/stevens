# 03. Поведение

Как всё работает. Внешний вид — в `02-screens.md`.

## 1. Режимы и запуск

**Режимы:** `sandbox` (песочница) и `account` (аккаунт). Экран входа — не режим, а то, что видно до выбора.

**При открытии страницы:**

1. Сразу `GET /api/health` (раздел 5) — параллельно со всем остальным.
2. Если флаг `auth` выключен → режим `sandbox`, сразу приложение.
3. Если в хранилище есть токен → `GET /api/auth/me`. 200 → режим `account`, приложение. 401 → токен удалить, экран входа с `auth_session_expired`. Нет сети или сервер спит → ждать вместе с health; не дождались за 60 с → экран входа со `status_server_down`.
4. Иначе, если раньше выбрали песочницу (`stevens:v1:mode` = `sandbox`) → режим `sandbox`, приложение.
5. Иначе → экран входа.

**Вход / регистрация:** проверить поля на фронте (раздел 8) → `POST /api/auth/login` или `/register` → сохранить токен и логин, `mode = account`, открыть приложение. Лента — восстановленная для этого аккаунта или пустая (раздел 7), новый `conversation_id`.

**Песочница:** кнопка `auth_sandbox_button` → `mode = sandbox`, приложение. `client_id` создаётся при первом открытии сайта и не меняется.

**Выход** (`menu_logout`): `POST /api/auth/logout` (ответ не ждать, ошибки игнорировать) → удалить токен → экран входа. `mode` удалить.

**«Войти или зарегистрироваться»** из песочницы: `mode` удалить → экран входа. Песочница и её лента остаются на устройстве.

**Сброс песочницы:** окно подтверждения → `POST /api/sandbox/reset` → при успехе лента очищается (стартовый экран), новый `conversation_id`. При ошибке — окно закрыть, в строке статуса `err_network` / `err_server` на 6 с.

**Заголовки запросов:** в режиме `account` — `Authorization: Bearer <token>`; в режиме `sandbox` и при выключенном `auth` — `X-Client-Id: <client_id>`. Health и вход/регистрация — без них.

**401 на любом запросе в режиме `account`** → удалить токен → экран входа с `auth_session_expired`.

## 2. Отправка сообщения

**Что отправляется:** текст из поля (Enter или кнопка), распознанный голос (сразу после остановки, без правки), нажатая кнопка ответа, нажатый пример.

Запрос `POST /api/chat`:

| Поле | Значение |
|---|---|
| `conversation_id` | текущий (раздел 7) |
| `text` | текст поля, обрезанный по краям / распознанный текст / `send.text` кнопки или её `label`, если у кнопки `send.action` |
| `source` | `text` / `voice` / `button` (примеры — тоже `button`) |
| `action` | `send.action` кнопки, иначе `null` |
| `client_time` | «сейчас» в ISO со смещением (в режиме заглушек — тестовые часы) |
| `timezone` | `Intl.DateTimeFormat().resolvedOptions().timeZone` |

**Порядок:**

1. Пустой или из пробелов текст не отправляется.
2. Сообщение пользователя сразу появляется в ленте (кнопка — её `label`, голос — с иконкой микрофона).
3. Поле очищается; на компьютере фокус остаётся, на телефоне — снимается.
4. Лента прокручивается вниз (всегда, даже если человек был выше).
5. Кнопки всех прошлых ответов гаснут; нажатая кнопка становится «выбранной».
6. Через 0,3 с — индикатор «Думаю», через 8 с — `thinking_slow`.
7. Ответ пришёл → индикатор заменяется ответом.

**Во время ожидания:** печатать можно, отправить нельзя (Enter ничего не делает, кнопка неактивна), микрофон неактивен, «Новый диалог» неактивен. Новые примеры и кнопки нажать нельзя.

**Таймаут:** 25 с после отправки (60 с, пока сервер просыпается) → ошибка `err_timeout`.

## 3. Ответ

1. Проверить ответ схемой (zod по `src/api/types.ts`).
   - Не прошёл, но есть строка `text` → показать как ответ из одного текста (без карточек и кнопок).
   - Не прошёл и `text` нет → ошибка `err_server`.
2. Нарисовать по `02-screens.md`, раздел 2.3. Незнакомый `kind` — не ошибка: рисуем по общим полям.
3. `kind: "error"` → показать `text` ответа как ошибку со значком и кнопкой «Повторить».
4. Карточки с `marks: ["new"]` подсвечиваются 2 с (только у свежего ответа).
5. Ответ объявляется экранному диктору (лента — `role="log"`, `aria-live="polite"`).

**Кнопки ответа:** активны только у последнего ответа ассистента. Нажатие → отправка (раздел 2), надпись кнопки — сообщением пользователя. Ответ «ждёт ответа» (`awaiting_reply`), но человек может вместо кнопки написать что угодно — это нормально.

## 4. Ошибки и «Повторить»

| Что случилось | Текст |
|---|---|
| fetch бросил ошибку (нет сети, CORS) | `err_network` |
| нет ответа за 25 с (60 с при пробуждении) | `err_timeout` |
| HTTP 5xx или 422 | `err_server` |
| HTTP 401 в аккаунте | выход на экран входа (раздел 1) |
| 200, `kind: "error"` | `text` ответа |
| ответ не прошёл схему и без `text` | `err_server` |

**«Повторить»:** отправляет тот же запрос ещё раз (тот же текст, source, action, свежий `client_time`). Сообщение пользователя не дублируется; ошибка заменяется индикатором «Думаю». Активна только у последней ошибки; новая отправка гасит её.

## 5. Сервер просыпается

Бесплатный сервер засыпает, первый запрос может идти до минуты.

1. При открытии — `GET /api/health`, таймаут 60 с.
2. Нет ответа за 1,5 с → в строке статуса `status_waking`.
3. Пока ждём, всё доступно: можно печатать, нажимать примеры, отправлять. Отправленное сообщение ждёт: индикатор в ленте сразу с текстом `status_waking` (без точек и без ожидания 8 с; с Д14 персонаж при этом «думает»), запрос уходит, как только health ответит (таймаут чата в это время — 60 с от отправки).
4. Health ответил → статус убрать, обычная работа.
5. Не ответил за 60 с → `status_server_down` постоянно; ждавшее сообщение — ошибка `err_timeout`. «Повторить» снова пробует (и снова будит).

## 6. Голос

Отдельный модуль `voice` с интерфейсом `isSupported()`, `start()`, `stop()`, `cancel()` и событиями `state`, `interim`, `final`, `error`, `level`. Если браузерное распознавание не взлетит, модуль заменят на серверное (`POST /api/stt`) — остальной код не меняется.

**Движок:** Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`), `lang = "ru-RU"`, `interimResults = true`, `continuous = false`. Громкость для столбиков — отдельно через `getUserMedia` + `AnalyserNode` (10–15 раз в секунду); при `prefers-reduced-motion` столбики стоят.

**Нажатие микрофона:**

| Ситуация | Что происходит |
|---|---|
| Браузер не поддерживает | запись не начинается; в строке статуса `voice_unsupported` |
| Первый раз, браузер спрашивает разрешение | пока висит вопрос — `voice_permission` |
| Доступ запрещён | `voice_denied` |
| Микрофона нет | `voice_no_mic` |
| Всё в порядке | режим записи (`02-screens.md`, 2.6) |

**Во время записи:**
- Промежуточный текст — в строке записи. Был текст в поле — распознанное продолжает его через пробел.
- Поле ввода заблокировано, «Новый диалог» неактивен.
- Остановка: пауза 2,5 с после последних распознанных слов (браузер слушает непрерывно, сам не обрывает) / «стоп» / 20 с записи.
- После остановки — итоговый текст (поле + распознанное) сразу отправляется с `source: "voice"`. Если распознано пусто → `voice_no_speech`, в поле возвращается то, что было до записи.
- Корзина → отмена: ничего не отправляется, в поле возвращается то, что было до записи.
- Вкладку свернули (`visibilitychange` → hidden) → отмена, как корзина.
- Сбой движка → `voice_error`, в поле — то, что было до записи.

Все подсказки голоса — в строке статуса, не в ленте; исчезают через 6 с или при следующем действии.

## 7. Хранение в браузере

Все обращения к `localStorage` — в `try/catch`. Хранилище недоступно → работаем без сохранения, ничего не падает.

| Ключ | Что | Пишется | Стирается |
|---|---|---|---|
| `stevens:v1:client_id` | UUID песочницы | первое открытие сайта | никогда |
| `stevens:v1:mode` | `sandbox` | выбор песочницы | выход, «Войти или зарегистрироваться» |
| `stevens:v1:token` | токен | вход, регистрация | выход, 401 |
| `stevens:v1:login` | логин (для кружка и меню) | вход, регистрация | выход, 401 |
| `stevens:v1:feed:sandbox` / `stevens:v1:feed:user:<id>` | `{ savedAt, messages }` — до 50 последних сообщений ленты этого режима | после каждого сообщения | «Новый диалог», сброс песочницы, при чтении — если `savedAt` старше 60 мин |

При старте ключи с другой версией (`stevens:v0:…` и т. п.) удаляются.

**Восстановление ленты** (при открытии приложения в режиме):
- Сохранённой ленте меньше 60 мин → показать её **только для чтения**: все кнопки погашены, подсветка новых и анимация появления не повторяются.
- Если последним было сообщение пользователя без ответа (обновили страницу во время ожидания) — его в ленте не показывать, а вернуть его текст в поле ввода.
- Диалог всегда продолжается с **новым** `conversation_id` (сервер мог забыть незаконченное уточнение).
- Старше 60 мин или ничего нет → стартовый экран.

**`conversation_id`** — новый UUID: при открытии приложения, «Новом диалоге», входе, выходе, сбросе песочницы.

Записи (планы) на фронте не хранятся и не кэшируются: источник правды — бэк.

## 8. Проверка полей входа

Проверяется при отправке формы, ошибка снимается при правке поля.

- Логин: после обрезки пробелов 3–32 символа, только буквы (русские и латинские), цифры, `.`, `-`, `_` → иначе `auth_err_login_format`. Регистр не важен (на бэк отправлять как ввели, сравнивает бэк).
- Пароль: не короче 5 символов → иначе `auth_err_password_short`. Пробелы по краям не обрезать.
- Ответы бэка: 401 `invalid_credentials` → `auth_err_credentials` (общая ошибка); 409 `login_taken` → `auth_err_login_taken` (под логином); 422 → соответствующая ошибка поля; сеть / 5xx → `err_network` / `err_server` (общая).

## 9. Прокрутка

- Своя отправка — всегда вниз.
- Пришёл ответ: человек внизу (ближе 200 px к низу) → плавно вниз; выше → не трогать, показать «↓ К новым».
- Раскрытие «Показать ещё» ленту не прокручивает.

## 10. «Новый диалог»

Окно подтверждения → «Начать»: лента очищается (стартовый экран), сохранённая лента режима стирается, новый `conversation_id`, строка ввода сохраняет напечатанное. Планы на сервере не трогаются.

## 11. Клавиатура и доступность

- Enter — отправить, Shift+Enter — перенос строки.
- Всё доступно с клавиатуры, порядок Tab: шапка → кнопки последнего ответа → поле → микрофон → отправить.
- Обводка фокуса — только при навигации с клавиатуры (`:focus-visible`).
- У кнопок-иконок — `aria-label` из `texts.ts`.
- Новые ответы объявляются диктору (`aria-live="polite"` на ленте).
- Горячей клавиши микрофона нет.

## 13. Прочее

- Заголовок вкладки — `Stevens`. Иконка вкладки — буква «S» шрифтом Plex Serif, `--c-text` на `--c-surface`, SVG (временная — позже Матвей пришлёт отдельный логотип для вкладки; персонажа во вкладке нет).
- `<meta name="theme-color">` — два тега с `media="(prefers-color-scheme: light|dark)"`: `#FCFBF7` и `#191816`.
- Никакой аналитики и отправки логов наружу.
- Сбой отрисовки ловит граница ошибок: вместо белой страницы — текст `err_server` и кнопка перезагрузить страницу (`btn_retry`).
