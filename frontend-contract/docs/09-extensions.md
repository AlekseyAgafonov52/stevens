# 09. Как наложить допы на первый вариант

Цель: **один код**. Все флаги допов выключены — получается в точности первый вариант (без допов), пиксель в пиксель и поведение в поведение. Включаем флаг — добавляется ровно один доп и ничего больше не меняется.

Структуру кода решаешь ты. Ниже — обязательные правила и рекомендуемая схема, которая этого добивается проще всего.

## 1. Правила

1. **Первый вариант не переписывается под допы.** В его компонентах появляются только «точки расширения» (раздел 2) — пустые места, которые при выключенных флагах ничего не рисуют и ничего не меняют.
2. **Каждый доп живёт отдельно:** `src/extras/<доп>/` — свои компоненты, хуки, стили, тексты берёт из общего `texts.ts`. Удалить папку и флаг — проект собирается и работает как первый вариант.
3. **Флаг проверяется в одном месте** — на входе в точку расширения. Внутри допа флаг не проверяется повторно. Исключение — модуль `src/api/`: он читает флаги, чтобы собрать заголовок `X-Stevens-Features` (правило 7) и фильтровать заглушки (правило 8). Больше флаги нигде не читаются.
4. **Код допа не грузится, если флаг выключен:** подключать через динамический импорт (`React.lazy` / `import()`), чтобы сборка `minimal` не тащила календарь и персонажа (бюджет JS — 150 КБ gzip).
5. **Общие данные — через одно хранилище состояния** первого варианта (лента, режим, ожидание, запись). Допы читают его и подписываются на события, но не дублируют.
6. **CSS допа** подключается только вместе с допом (`mascot.css` — только при `d14_mascot`).
7. **Бэк знает, какие допы включены.** Модуль `src/api/` добавляет к каждому `POST /api/chat` заголовок `X-Stevens-Features` со списком включённых допов, которым нужен бэк: `d2`, `d3`, `d10` (через запятую). Ни одного не включено — заголовок не шлётся, и бэк отвечает ровно как для первого варианта (контракт v1.4, раздел 15.2). Так сборка `minimal` не получит от бэка кнопок «Отменить» и «Вернуть».
8. **Заглушки ведут себя как бэк.** В режиме заглушек модуль `src/api/` выполняет правила `meta` из `mocks.json`: `extras` (сценарии «ДОП» и кнопки `undo` / `restore` / `delete` / `complete` — только при включённом допе, иначе ответ как в первом варианте), `store` (одно хранилище записей в памяти на чат и календарь), `patch` (как меняется запись), `matching` (сопоставление, в том числе по `record_id`). Без этого после замены `mocks.json` в первом варианте появится кнопка «Отменить».

## 2. Точки расширения

Добавить в первый вариант (при выключенных флагах — пусто и без побочных эффектов):

| Точка | Где | Кто использует |
|---|---|---|
| `HeaderRightStart` | шапка справа, перед меткой режима | Д6: кнопка календаря |
| `LayoutSidePanel` | справа от ленты и строки ввода | Д6: панель календаря |
| `AnswerExtraButtons` | ряд кнопок под ответом, **первой** позицией | Д10: «Исправить» |
| `RecordCardOverride` | отрисовка карточки в ленте | Д10: форма правки на месте карточки |
| `RecordCardState` | вид карточки | состояние «Удалено» (`marks: ["deleted"]`, `07-extras.md`, раздел 5) — включается при `d2_delete` **или** `d10_undo`: «Отменить» (Д10) тоже присылает карточку «Удалено». Код — `src/extras/deleted-card/`, общий для обоих допов |
| `InputBarOverlay` | внутри контейнера строки ввода | Д14: персонаж |
| `LoginTitleAside` | справа от «Stevens» на экране входа | Д14: персонаж |
| `WaitingIndicator` | индикатор ожидания в ленте | Д14: заменяет точки на «только текст через 8 с» |
| `FeedBottomInset` | нижний отступ ленты | Д14: 84 / 74 |
| `onAssistantResponse(response, request)` | событие: пришёл ответ | Д6 (обновить календарь), Д12 (озвучить), Д13 (включить микрофон), Д14 (готово / не понял) |
| `onUiActivity(kind)` | события: `typing`, `recording-start`, `recording-stop`, `request-start`, `request-end`, `button-press` (нажата любая кнопка интерфейса), `new-dialog`, `tab-hidden` | Д14 (состояния), Д12 (оборвать речь), Д13 (отменить автослушание) |
| `voice.start()` из кода | уже есть в голосовом модуле | Д13 |

Остальное (например, Д3 в чате, «Какую именно?», «Вернуть») работает **без точек расширения**: это обычные ответы бэка и кнопки, которые первый вариант уже умеет рисовать по общим полям.

## 3. Проверка «флаги выключены = первый вариант»

**До начала допов** (после шага 10 плана):
1. Собрать с выключенными флагами допов и записать эталонные снимки Playwright: вход, стартовый экран, запись голоса, ожидание (`#slow`), запись создана, «не понял», телефон (вход и переписка), тёмная тема (вход и переписка).
2. Сверить их глазами с `reference/screens/mvp/`.

**После каждого допа:**
1. Выключить все флаги допов → прогнать те же снимки → **расхождений быть не должно** (допуск — сглаживание шрифта).
2. Прогнать ручной сценарий из шага 12 плана с выключенными флагами.
3. Сборка `minimal` не должна вырасти больше чем на 2 КБ gzip.

Если снимки расходятся — доп протёк в первый вариант; чинить в допе, не в первом варианте.

## 4. Наборы сборки

| Набор | Флаги | Для чего |
|---|---|---|
| `minimal` | все флаги допов выключены, `auth` выключен | запасная ссылка, как в первом пакете: первый вариант без входа, не зависит от готовности входа на бэке |
| `full` | `auth` (если бэк успел вход) + допы, которые прошли проверку | ссылка для жюри |

`auth` — не доп, а часть первого варианта со страховкой (если бэк не успеет вход — выключить, и приложение откроется сразу в песочнице). Эталонные снимки первого варианта (раздел 3) снимаются с `auth` включённым и всеми допами выключенными — как в `.env.development`.
