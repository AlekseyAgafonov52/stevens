# Stevens: надёжная обработка YandexGPT

## Быстрый запуск (PowerShell)

1. Сохраните `.env` из предыдущей установки и перенесите его в эту папку (не публикуйте ключ).
2. Остановите **старую** Compose-сборку из её собственной папки: `docker compose down` (БЕЗ `-v`).
3. В этой папке: `docker compose up -d --build`.
4. Сайт: http://localhost:8081. Журнал: `docker compose logs -f backend`.
5. Прямая проверка нейросети: `docker compose exec backend python -m tools.diagnose_llm`.
6. Отчёт за последние 7 дней: `docker compose exec backend python -m app.log_report`.

Важное различие: тест `tools.diagnose_llm` принудительно вызывает YandexGPT, не сохраняет записи. В интерфейсе сайта по умолчанию остаётся гибридный маршрут `rules/LLM`; в обычной речи не каждый запрос будет попадать в YandexGPT.

## Изменения

- Для невалидного JSON/схемы/явной подмены названия выполняется не более **одной** повторной попытки YandexGPT с инструкцией по исправлению.
- Только для просмотра расписания (`list`) можно безопасно восстановить пропущенный период из оригинального текста пользователя. Для создания, удаления и переноса подобное восстановление запрещено.
- Ошибка `invalid_parse_schema` больше не включает глобальную 60-секундную паузу LLM. Сетевая недоступность и таймауты по-прежнему запускают защитную паузу.
- `list` принимает дополнительный `query_mode`: `count`, `workload`, `summary`. Ответы строятся из записей PostgreSQL без выдуманных событий.
- Обновлены инструкции и тестовые фразы. Отображение `\\u041d` в диагностике — безопасное экранирование кириллицы, не ошибка.

## Тесты

В окружении с установленными `requirements.txt` и `requirements-dev.txt`:

```bash
python -m pytest tests/test_llm_resilience.py tests/test_llm_quality.py tests/test_history_five.py -q
```

Не выполняйте `docker compose down -v`, если нужны старые данные. Разные Compose-проекты с фиксированным именем контейнера `voice_assistant_db` одновременно запускать нельзя.

## Ограничения

Это отказоустойчивая обработка, а не обещание 100% точности. Естественные выражения, даты и контекстные переносы требуют проверки на реальном YandexGPT и тестов в интерфейсе. В случае двух неудачных ответов модель не делает небезопасного действия, а система возвращается к правилам / уточнению. Вопрос «Много ли дел?» оценивается по числу записей, а не по реальной длительности работы.
