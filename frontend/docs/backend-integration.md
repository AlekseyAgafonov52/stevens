# Реализованная интеграция: приоритет существующего backend

Прямое указание владельца: API при расхождениях адаптировать к текущему Python-коду. Исходные документы 01–06 и PDF сохранены без переписывания продуктовой истории. Этот файл описывает отличия данной реализации.

| Спецификация архива | Фактическая интеграция |
|---|---|
| login/password | email/password; регистрация дополнительно name |
| Пароль от 5 | Регистрация от 6 до 128; вход не ужесточаем до 6 |
| User: id/login | id/email/name |
| /me: {user} | объект пользователя напрямую |
| Ошибки error:code | detail: строка либо массив Pydantic |
| GET /api/health | GET /; только проверка HTTP-доступности |
| X-Client-Id sandbox | Только локальный mock; real требует вход |
| /auth/logout | Только очистка локальной сессии |
| /sandbox/reset | Только сброс ленты демонстрации, сервер не вызывается |
| Button.send с одним ключом | Принимаются Pydantic text:null/action:null и нормализуются |
| action | Не отправлять серверу, который его игнорирует: показать ошибку поддержки |

Сборка minimal оставлена в mock: отключение auth не создаёт поддержку гостевого режима на backend. full использует реальный API. Уточнения в real режиме отображаются, но серверная память диалога не реализована. Подтверждения/совпадения демонстрируются на моках.

Дизайн из архива сохранён; необходимые email/имя, объяснения режимов и недостающие размеры добавлены централизованно в texts.ts/tokens.css. Тема системная, шрифты локальные из @fontsource, иконки lucide-react, UI-библиотек и аналитики нет.

Python-файлы, PostgreSQL и алгоритм YandexGPT в этой задаче не изменялись. Ключи не читаются и не копируются во фронтенд. Живые серверные сценарии требуют отдельного работающего backend.
