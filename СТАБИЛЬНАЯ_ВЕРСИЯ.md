## Исправления этого прохода

После исходного прохода переработан резервный ИИ-разбор: [ПЕРЕРАБОТКА_BRAIN.md](ПЕРЕРАБОТКА_BRAIN.md). Старые `IntentSchema` и исправления дат/названий из `brain.py` заменены контрактной схемой и проверенным адаптером. Правила остаются первым способом разбора; новые действия через LLM не включены.

- В импорте явно типизирован разнородный снимок записи, проверяются необязательные идентификаторы, строка повтора собирается без операции над возможным `None`. Блокировка владельца разделена для аккаунта и песочницы.
- В прежнем API переноса проверяются результаты создания записи и разбора идентификатора серии; убраны обращения к необязательной дате и бессмысленное выражение из двух `pop`.
- В NLU проверяются относительная дата и период до вычислений; ссылка на морфологический анализатор фиксируется перед использованием во вложенной функции.
- Push-транспорт сохраняет совместимую сигнатуру `requests.Session.request`, принудительно проверяет TLS и отключает перенаправления и прокси. Пустой или неожиданный результат отправки больше не считается доставкой. Наличие сохранённого ключа VAPID проверяется явно.
- Возвращаемый тип `series.create` теперь честно допускает отсутствие серии, если нет подходящих дней. Старые `type: ignore` из приложения и `brain.py` удалены. Инструмент LLM описан типом SDK; `strict: false` явно сохраняет нестрогий режим разбора, без изменения полей ответа Stevens. Запрос проверен с подменённым SDK-транспортом.
- Исправлены аннотации диагностических аргументов и проверки отсутствующих записей/ответов в тестах. Моки отделены от типа реальной сессии БД.
- `audit_run_tests.py` возвращает ошибку при ненулевом коде, таймауте или напечатанном провале старого теста. Неизвестное имя теста также завершается ошибкой. Отдельный `test_brain.py` теперь возвращает ненулевой код при провале.
- В `.devcontainer/start.sh` исправлены CRLF, ломавшие Bash. `.gitattributes` закрепляет LF для `.sh`.
- Добавлены общая конфигурация Pyright и отдельные зависимости проверок. Временные результаты исключены из контекста Docker. Переписаны устаревшие инструкции запуска.

Новые проверки `tests/test_project_safety.py` покрывают ответы push, настройки транспорта, ложный успех старых тестов и структуру запроса LLM. Вместе с `tests/test_chat_safety.py` это 12 отдельных unit-тестов; они входят в общий прогон 23 файлов.

## Как повторить

Полные команды и отдельная тестовая БД описаны в [ЗАПУСК.md](ЗАПУСК.md).

```sh
python -m pip install -r requirements-dev.txt
npx --yes pyright@1.1.414
python audit_run_tests.py
```

Последняя команда требует запущенной отдельной PostgreSQL на порту 55439. Результаты хранятся в игнорируемом `audit-results/`. Браузерные артефакты находятся в игнорируемом `fix-results/`. Их не нужно коммитить.

Для применения версии к обычному локальному запуску:

```sh
docker compose up --build -d
```

## Границы проверки

Рабочие контейнеры `voice_assistant-*` и их данные не изменялись. Временные контейнеры и сеть общего прогона удалены после проверки. Коммит и публикация не выполнялись.

Реальные запросы к Yandex, доставка push на устройство, физический микрофон, Safari/iPhone и длительная работа под нагрузкой здесь не проверены. Отдельный `test_brain.py`, вызывающий живую модель, статически проверен, но с настоящим провайдером не запускался. Пять предупреждений Fast Refresh, существующие административные задачи по HTTPS/резервным копиям и отдельные вопросы соответствия контракту остаются за пределами подтверждённого результата.
